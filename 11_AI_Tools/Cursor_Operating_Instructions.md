# Cursor Operating Instructions

## Purpose
Use Cursor for the role defined in Tool_Routing_Matrix.md.

## Best Use
Work inside approved GaryOS or Projects folders after reading the relevant local instructions.

## What It Should Not Do
Do not change security settings, credentials, production configuration, client raw data, or external communications without explicit approval.

## Approved Working Folders
- The GaryOS repository root
- Explicitly approved project repositories
- Explicitly approved sandbox folders

## Files To Read First
- GaryOS_Master_Instructions.md
- 00_System_Profile/Machine_Profile.md
- 17_Improvement_Loop/Self_Improvement_Rules.md

## Files It Should Never Touch
- Secrets, tokens, API keys, passwords, certificates, browser profiles, production data, and system security settings.

## How It Should Use GaryOS
Capture findings, log improvements, use tests for changes, and publish approved standards into registries.

## How It Should Log Improvements
Use Issue_Log.md, Agent_Findings.md, Prompt_Registry.md, Workflow_Registry.md, SOP_Registry.md, Test_Log.md, and Release Notes.

## How It Should Test Changes
Use the testing workbenches and record old output, new output, score, result, and decision.

## Approval Queue Trigger
Create an approval item for client-facing deliverables, external communications, production scripts, security controls, financial records, legal records, employment documents, tool configuration changes, system configuration changes, and anything outside approved folders.
